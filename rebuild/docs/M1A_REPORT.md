# FitQuest M1a — durable local logging evidence

Date: 2026-09-23 (America/New_York). Scope: the owner-approved M1a handoff under `rebuild/`. **Result: local synthetic profile/session logging, encrypted native persistence, and fail-closed Release fixture gating verified on an iPhone 17 Pro simulator.** This is partial product acceptance; real identity and synchronization are not implemented.

## Changed source

- `packages/contracts/src/index.ts` and `m1.test.ts`: strict Zod schemas for minimal profile, quantities/load basis, strength and manual-time results, activities, sessions, and versioned commands; pure session transition checks. Health liveness remains unchanged. Null is unknown; zero is explicit. Stable activity/result IDs cannot disappear by omission, and result kinds cannot change under an existing ID. Session local date is derived from its start and recorded IANA time zone. Defensive limits are name 80–120 characters, notes 1000, decimals 9 integer/3 fractional digits, repetitions 100000, RPE 10, RIR 100, and bounded activity/result counts. These are input safeguards, not training prescriptions.
- `apps/mobile/src/access.ts`: an injectable provider-independent local access interface and a development-only fixture adapter for two synthetic identities. The adapter keeps durable active/generation/revocation/expiry state in SecureStore and checks generation before reads/writes. Ordinary synthetic expiry allows local capture; sign-out/switch/revocation locks old work. Release never reads fixture authorization. This store implementation still intentionally opens only synthetic fixture namespaces; a later production adapter needs its own account scope.
- `apps/mobile/src/store.ts`: one SQLCipher database and separate 32-random-byte SecureStore key per synthetic account, checked owner/environment, migration version and SHA-256 checksum, WAL/foreign-keys/synchronous FULL, serialized writes, bound user values, immutable history/command rows, and raw draft storage. Every accepted profile/session save writes projection, revision, and queued command in one exclusive transaction. Expo's exclusive transaction opens a second native connection, so its transaction handle receives the same key before its first schema access. There is no sender or fabricated receipt.
- `apps/mobile/src/store.test.ts`: headless tests run the **repository's real SQL** through an in-memory SQLite adapter, injecting rollback after projection, history, and command writes; verify retry idempotence, draft separation/reopen, and generation rejection. Native encryption is verified separately in the simulator.
- `apps/mobile/App.tsx`: Sessions-first profile, multiple unplanned sessions, strength/manual-time entry and correction, explicit activity/session outcomes, durable raw draft status, failed-save feedback/retry, local status details, and developer-only synthetic test controls. Shared labeled controls use provisional neutral/teal colors and flexible text heights.
- `apps/mobile/app.json`, mobile/root package manifests and lockfile: SQLCipher native config, SDK-compatible `expo-sqlite` 57.0.3, `expo-secure-store` 57.0.4, `expo-crypto` 57.0.3, `expo-file-system` 57.0.7; mobile repository test included in `npm run check`. `README.md` now documents the repeatable local workflow and fixture boundaries.

The [Expo SQLite guide](https://docs.expo.dev/versions/latest/sdk/sqlite/) documents the SQLCipher config/PRAGMA and transaction API. The checked-in SDK 57 `SQLiteDatabase.ts` implementation confirms `withExclusiveTransactionAsync` creates a new connection before invoking the callback; this was also observed as an initial native `file is not a database` failure until that connection was keyed. The [Expo SecureStore guide](https://docs.expo.dev/versions/latest/sdk/securestore/) documents `WHEN_UNLOCKED_THIS_DEVICE_ONLY` and iOS Keychain persistence considerations. The [Expo FileSystem guide](https://docs.expo.dev/versions/latest/sdk/filesystem/) supplies the existing-file check. Key loss and metadata mismatch retain the database and show recovery errors; there is no plaintext fallback or automatic reset.

## Limits and next engineering gate

This slice has no real Sign in with Apple, provider verification, server sender, server revisions/receipts, conflict resolution UI, hosted database/RLS verification, physical-device Keychain/locked-device test, Android native test, VoiceOver walkthrough, HealthKit, AI, or coaching. The simulator's wrong/missing-key checks used separate native connections, not deletion of a stored SecureStore key. The owner/checksum fault checks mutated metadata only inside rolled-back diagnostic transactions. SQLCipher's behavior on device backup/reinstall and physical hardware remains unverified. The Debug app requires local Metro; Release fails closed until a real auth slice is approved.

No shared `docs/`, prototype, backend athlete route, hosted migration, Apple account, LAN endpoint, credential, or Git state was changed. HQ owns the shared handoff. Recommended next task after HQ review: a separately scoped real-account authentication and authenticated synchronization increment, starting with physical-device identity/key recovery gates and server operation idempotence; retain these local command and draft semantics.
