# M1c.1 engineering report — auth contracts and recovery model

Date: 2026-09-25. Scope: the approved local M1c.1 increment only. This is a model and contract delivery for HQ review, not real sign-in or M1c acceptance.

## Files and contract surface

- `packages/contracts/src/auth.ts` adds strict Zod schemas for an empty challenge request, Apple challenge/exchange, complete pending credentials, activation, refresh, logout, active identity and bounded auth errors. It exports a versioned single-bundle persisted union (`stable`, `refresh_prepared`, `activation_pending`, and terminal `reauth_required`) plus separate local-authorization binding/result types. The defensive wire bounds are nonce/state 1–512 characters, identity token 1–16384, authorization code 1–4096, access token 1–8192, refresh/revocation tokens 1–4096, positive safe credential generations, UUIDs and ISO instants. Activation cannot outlive access or refresh; access cannot outlive refresh or session; refresh cannot outlive the absolute session deadline. Unknown fields are rejected.
- `packages/contracts/src/index.ts` adds only the auth export. Existing M1b `IdentityResponseSchema`, command canonicalization, domain errors and stored operation formats are unchanged.
- `apps/mobile/src/auth/coordinator.ts` adds a framework-free coordinator and injected clock/operation-ID, fenced conditional credential storage/readback, local-authorization inspect/authorize/lock, explicit expected account/store/install context, current-scope, and exchange/refresh/activation/identity/revocation transport ports. The transport returns typed outcomes; public snapshots contain only phase, local/sync availability, server-logout-pending and a bounded code. The file declares configurable client retry limits and named proposal timing defaults; server-supplied deadlines are never extended by client time.
- `packages/contracts/src/auth.test.ts` and `apps/mobile/src/auth/coordinator.test.ts` contain focused schema and deterministic fake-port tests. No runtime app, existing mobile access/store/sender, API, migration, native adapter, package manifest, or dependency was changed.

## Recovery behavior modeled

The rotating bundle is written and read back as `refresh_prepared` before refresh dispatch; a returned complete bundle is written and read back as `activation_pending` before activation. Activation is followed by a separate matching identity check, durable local-authorization acknowledgement, and a stable write/readback before `syncReady` becomes true. A definite same-operation reauthentication outcome is persisted as terminal `reauth_required`; a lost response leaves `refresh_prepared` for exact-operation retry. The model never returns issued secrets from a replay cache or reconstructs a partial bundle.

An uncertain initial exchange requires fresh authorization and is never sent again automatically. A complete received bundle kept only in memory can make two bounded storage retries before its authoritative activation deadline; it does not survive process death. A durably stored pending bundle can retry activation before its deadline. After that deadline, but while its access bearer remains valid, one bounded idempotent check lets the server distinguish a genuinely expired pending session from an already-active generation. Matching activation and identity confirmation are still required; the client never extends the server deadline. A mismatched identity, owner, environment or session cannot unlock records. A verified fresh session for the same account can rebind local authorization; a different account cannot silently take it over.

Ordinary token expiry, missing rotating credentials, and provider outage leave independently valid local authorization available while sync is unavailable. An explicit local lock remains locked on restart even if a stable bearer was retained. Logout/switch invalidates the coordinator immediately, requires a durable local lock acknowledgement before reporting completion, and can report server sign-out pending if revocation is offline. Failure of every lock write reports `logout_incomplete`. Conditional storage and authorization ports check a captured environment/account/session/epoch/generation guard at commit, so delayed writes or callbacks cannot install work after stop/switch/newer generation. Cleanup uses only the received abandoned bundle's revocation capability and is bounded.

## HQ F1–F4 correction

- **F1:** `recover()` reads and retains the credential record/revision as a fenced CAS candidate even when independent local authorization is durably locked; it never unlocks from that record. A fresh verified exchange for the same account can replace the retained bundle, including under a newer local epoch. A different account or expected store owner is rejected without replacing the retained record. Lock failure remains `logout_incomplete`; a delayed or conflicting credential write cannot install the fresh bundle.
- **F2:** access expiry with an unexpired refresh and absolute session deadline is `local_only / ACCESS_EXPIRED`, with local logging retained and sync unavailable. `refresh()` can then prepare and dispatch one exact-operation rotation. Expired refresh or session authority remains terminal `reauth_required` and cannot dispatch.
- **F3:** a stored pending bundle with an expired activation deadline can make one idempotent status check while its access bearer is valid. Only a server response marked already active with matching activation and identity can become ready. Server-expired pending, a late new activation, and expired access remain unready.
- **F4:** independent local authorization is schema-validated against environment, epoch and any trusted expected account/store/install/session context before exposing `localAccess: authorized`, including when rotating credentials are missing, malformed or unreadable. Contradictions durably lock; temporary protected-storage unavailability reports locked access. A valid missing-credentials record remains local-only.
- **F5:** a malformed rotating bundle retains only its storage revision as a CAS candidate. Recovery remains local-only when a valid local binding and independently complete account/store/install owner agree; otherwise it reports explicit locked `recovery_required / AUTH_RECOVERY_REQUIRED`. The coordinator never reads owner or tokens from the malformed bundle. Fresh exchange can replace that revision only with a complete, verified same-account bundle, followed by durable pending write/readback, activation, identity confirmation, local authorization acknowledgement, and stable write/readback. A different account leaves the damaged record and local work intact. Failed write/readback supports bounded retry of the received complete bundle; a newer revision or epoch prevents its installation. A superseded repair snapshot no longer exposes stale local authorization.

## Limits and next task

These tests prove coordinator reactions under the stated fake-port contracts. They do not prove native SecureStore/SQLCipher durability, Apple exchange or JWT verification, PostgreSQL session replay/revocation enforcement, actual network cancellation, signing, device behavior, or hosted security. No PostgreSQL or native checks were run because those runtime paths did not change. The app and default API remain in their accepted M1b behavior; real sign-in remains locked.

HQ should review M1c.1 before separately assigning M1c.2 account/store boundary separation. That next increment must implement and test the real-account namespace and authorization fences without migrating or promoting the retained synthetic fixtures.
