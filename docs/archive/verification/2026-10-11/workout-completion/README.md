# Saved workout completion — October 11, 2026

The owner assigned a clear completion indicator on Week and Today. Document-plan cards, Today's featured session/list and the workout detail show a green checkmark with **Completed** only when a server-saved journal has outcome `completed` for the exact account, plan ID, accepted revision, prescribed date and session index. Missing, in-progress, partial and skipped logs are not marked complete. One finished occurrence is sufficient; an unfinished repeat does not erase an earlier completed occurrence. Reopening the only completed log removes the badge after the next read. Changed plan revisions do not inherit completion.

The new authenticated, no-store `GET /workout-journal/completed-sessions?planId=…&revision=…` returns at most 84 date/session references, never notes, actuals or snapshots. It reuses the existing account/source index and owner-scoped session-guarded transaction. It does not page through history, infer completion from prescriptions or write records. No migration, grant change or paid call is needed. The mobile read refreshes on return from the journal, app foreground and account/plan changes, rejects late/mismatched responses, and offers a retry without blocking workouts if unavailable. An unresponsive request times out after 15 seconds.

Component regressions cover finish/reopen, independent sessions, retry/foreground refresh, malformed/mismatched data, expired authentication and late former-account responses. Isolated PostgreSQL tests cover all outcomes, exact source/revision/account matching, repeated occurrences, more than 50 history entries, reopening and revoked sessions. An HTTP regression checks authenticated identity, the minimal response and no-store behavior. Final source/CI identity is reported in the implementation handoff; mocked and synthetic checks do not establish physical-phone acceptance.
