# Bounded output-format comparison

This is a diagnostic-only harness, not an application path or a production change. `scripts/format-comparison.mjs` prepares the current complete-week request and an otherwise identical plain-text variant. It removes `text.format` and changes only the final format sentence, retaining catalog bytes, answers, dates, model, reasoning and weekly limits. The saved non-private request diff records those exact differences.

The owner-authorized fixed baseline is `backend/.ai-evaluation/owner-baseline-v1.json`. It contains the original answers and verified source metadata, with an answer fingerprint. Reuse that file for future **explicitly authorized** comparisons until the owner requests custom inputs. Do not replace it with newer answers, reconstruct it from memory, commit it, or use it to alter production intake. The containing directory is mode 700 and private files are mode 600; `.ai-evaluation/` is Git-ignored.

The October 7 pair is complete. Its private report is `.ai-evaluation/format-pair-comparison.html`; original outputs are `format-pair-A-output.txt` and `format-pair-B-output.txt`. The private report contains the actual output assessment, source/correlation evidence, costs and preservation checks. No output, answer, prompt or personal source metadata belongs in this document or synthetic tests.

The harness atomically reserves both attempts through the existing hosted `reserve_onboarding` function, uses purpose `evaluation`, and settles each through the existing store. Cumulative maximum reservations cannot exceed $0.10, with the existing lifetime/evaluation caps still enforced. A permanent local started marker and hosted prompt-version check prohibit repeating this pair, including after an interrupted run. It never retries or initializes/reset budgets, Auth/profile fixtures, owner plans or schema. An uncertain outcome retains its reservation and requires inspection. Do not delete markers or rename the batch to obtain a rerun without new owner authorization.

The diagnostic adapter uses the same 48,000-output-token, 450,000-input-byte, 512,000-response-byte and 180-second limits for both variants. Production's adapter chooses weekly bounds from the JSON format name; removing it there would otherwise select onboarding limits. Production code remains untouched. Raw private output is saved before settlement/validation, and a file-write failure still attempts charge settlement. Plain text is not converted into a valid application plan.

Five synthetic tests in `scripts/format-comparison.test.mjs` verify exact request differences, identical catalog/settings, plain output beyond onboarding limits, one dispatch per variant, settlement before validation, incomplete/network outcomes without retries, and accounting despite private-output write failure. Run these after the ordinary backend build; they make no network calls and need no server. Real comparison attempts were separately read back as settled, and owner content plus all historical accounting records were verified unchanged.

One sample per condition cannot establish causality. Schema removal also removes its descriptive guidance, and the necessary formatting sentence changes. No production fix, release or paid follow-up is implied by the results.
